# csARM — производительность на телефоне: план и приоритеты

Порт сейчас проходит путь кадра через **две** трансляции:

```
Valve DX9 (shaderapidx9)
      │  ToGL: DX9 asm → GLSL (рантайм, dx9asmtogl2)
      ▼
   GLM-контекст  →  gl4es (GL 2.1 → GLES2, всё на CPU)
      ▼
SwiftShader (CI/эмулятор)  или  драйвер GPU (телефон)
```

Каждый слой — это накладные расходы на **каждый вызов GL** и на **старт**
(трансляция шейдеров). Порядок работ — по соотношению «эффект / риск».

## 1. Убрать gl4es с горячего пути мира (наибольший эффект)
- Мир и так идёт через шейдеры (ToGL генерирует GLSL) — fixed-function нужен
  только VGUI2 и части UI. Разделить: `libGL` (gl4es) грузить только для UI,
  а GLM-контекст ToGL поднять напрямую на GLES3.
- Пока это не сделано: не вызывать gl4es-путь для мира, проверить, что
  `-noshaderapi`-ветка не используется в игровом прогоне.
- Ожидание: −20…40% CPU в кадре (gl4es — чистый CPU-оверхед: батчинг,
  конвертация состояний, FFP-эмуляция).

## 2. Шейдеры: офлайн-трансляция + дисковый кэш
- Сейчас DX9-байткод транслируется в GLSL при загрузке каждого варианта.
  На холодном старте это секунды, в игре — микрофризы на первом появлении
  материала.
- План: хэш байткода → файл `shaders_cache/<hash>.glsl`; при первом запуске
  транслируем и сохраняем, далее только читаем (`files/` внутри sandbox,
  переживает перезапуск).
- Дополнительно: предзагрузка кэша для карты при старте (в фоне).

## 3. Текстуры и память
- VTF (DXT/BGRA) → **ETC2/ASTC** офлайн (`vtex` + `astcenc`) — меньше памяти,
  меньше трафика, GPU ест нативно.
- `mat_picmip 2`, `r_lod 1` (уже в `android/assets/cstrike/cfg/autoexec.cfg`).
- Звук `.wav` → ogg/opus: экономия десятков МБ и декода.

## 4. Пост-обработка и разрешение
- `mat_postprocess_enable 0`, `mat_hdr_level 0`, `mat_motion_blur_enabled 0`
  (уже в autoexec): engine_post/bloom/blur — полноэкранные пассы, на мобиле
  дороже самой сцены.
- Рендер в 720p RT и апскейл на композитор (движок уже рисует 1080×720 в окно
  1080×2280).

## 5. Потоки / big.LITTLE
- `mat_queue_mode 2`, `host_thread_mode 2`, `cl_threaded_bone_setup 1` — есть.
- Дальше: affinity главного GL-потока на big-ядра, job-пул на little;
  проверить, что серверный тик не крутится вхолостую в меню.

## 6. Как мерить (а не гадать)
- `simpleperf record -p <pid>` + `dumpsys gfxinfo` + Perfetto-трейс кадра.
- Метрики: p95 frame time на `ar_dizzy` @720p, RSS (`dumpsys meminfo`),
  время до первого кадра.

## 7. Старт
- Холодный старт = монтирование VPK + загрузка карты + трансляция шейдеров.
  После п.2 останется только I/O — прогрев кэша на первом запуске со сплэшем.
